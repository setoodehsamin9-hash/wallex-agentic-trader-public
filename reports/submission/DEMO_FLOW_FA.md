# مسیر دموی پنج‌دقیقه‌ای — فقط شواهد ثبت‌شده

وضعیت: آمادهٔ استفاده با run موجود؛ ویدئو و شواهد LIVE آینده **PENDING** هستند.
هیچ فرمان این راهنما سفارش نمی‌فرستد، مدل را صدا نمی‌زند یا journal را تغییر نمی‌دهد.

قبل از ضبط: شناسهٔ اجرا و فایل SQLite آن را مشخص کنید. نمونهٔ زیر به `var/state.sqlite` اشاره دارد؛
برای BACKTEST معمولاً `--db backtest.sqlite` لازم است. پوشهٔ خروجی باید تازه باشد.

```bash
uv run wallex-agent status RUN_ID --db state.sqlite
uv run wallex-agent demo-evidence RUN_ID --db state.sqlite
uv run wallex-agent explain RUN_ID --db state.sqlite --last 3
uv run wallex-agent performance RUN_ID --db state.sqlite
uv run wallex-agent evidence export RUN_ID --db state.sqlite --out evidence/RUN_ID
uv run wallex-agent evidence verify evidence/RUN_ID
```

| زمان تقریبی | نمایش و توضیح |
|---|---|
| ۰:۰۰–۰:۳۰ | شناسه، محیط BACKTEST/SHADOW/LIVE، حالت اختیار، زمان آخرین شاهد و نوع SIMULATED/EXCHANGE را بخوانید. دادهٔ تاریخی سلامت لحظه‌ای ربات را ثابت نمی‌کند. |
| ۰:۳۰–۱:۱۰ | `demo-evidence` بند ۱: snapshot، کیفیت داده و featureهای ثبت‌شده؛ feature یعنی اندازه‌گیری عددیِ بازار. نبود شاهد را همان‌طور اعلام کنید. |
| ۱:۱۰–۱:۴۵ | بند ۲: کاندیدا، یعنی فرصت کامل ساخته‌شده با کد قطعی؛ نماد، قیمت و حد ضرر را مدل اختراع نمی‌کند. |
| ۱:۴۵–۲:۲۰ | بند ۳: تصمیم و توضیح کوتاه ذخیره‌شده. BASELINE انتخاب‌گر قاعده‌مند است و نباید AI واقعی معرفی شود؛ REPLAY فقط بازخوانی است. |
| ۲:۲۰–۳:۰۰ | بند ۴: حکم Risk و دلیل رد/کاهش/تأیید. موتور ریسک آخرین دروازهٔ معامله است. کد دلیل استراتژی اگر ذخیره نشده، ناموجود است. |
| ۳:۰۰–۳:۴۰ | بند ۵: نتیجهٔ اجرای ثبت‌شده و نتیجهٔ معامله اگر بسته شده است. WAIT یعنی صبر؛ REJECT یعنی رد؛ UNKNOWN یعنی نتیجهٔ سفارش معلوم نیست. هیچ‌کدام را معاملهٔ موفق معرفی نکنید. |
| ۳:۴۰–۴:۲۰ | بند ۶ و `evidence verify`: زنجیرهٔ هش، checkpoint و بازسازی نتیجهٔ قابل‌مشاهده؛ نیازی به بازار، مدل یا کلید نیست. هش، اصالت بیرونی معامله را ثابت نمی‌کند. |
| ۴:۲۰–۵:۰۰ | بند ۷ و گزارش عملکرد: سود محقق/باز، کارمزد، افت، پوزیشن باز و REAL WRITE. نتیجهٔ شبیه‌سازی را به سود واقعی اضافه نکنید. |

برای خروجی بایت‌به‌بایت تکرارپذیر، زمان UTC یکسان بدهید:

```bash
uv run wallex-agent evidence export RUN_ID --db state.sqlite --out evidence/take-1 --generated-at 2026-10-23T00:00:00Z
uv run wallex-agent evidence export RUN_ID --db state.sqlite --out evidence/take-2 --generated-at 2026-10-23T00:00:00Z
```

هش محتوای تکرارپذیر بدون زمان تولید محاسبه می‌شود؛ خود فایل زمان تولید نیز هش جداگانه دارد.
فرمان `evidence verify` فقط مشاهده را بازسازی می‌کند؛ فرمان قدیمی `replay` اجرای جدیدی در journal می‌سازد و جزو این مسیر فقط‌خواندنی نیست.

در قالب فعلی، شمارش کامل نوشتن‌های LIVE (از جمله لغو) قابل اثبات نیست و `UNKNOWN` نشان داده می‌شود.
صفرِ شبیه‌سازی فقط با تطبیق رخدادهای state و منبع شبیه‌ساز قابل گزارش است؛ نام محیط به‌تنهایی کافی نیست.
